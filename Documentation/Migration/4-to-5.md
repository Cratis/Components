---
title: Migrate from Components 4 to 5
description: Replace the table-based SchemaEditor with the tree editor, and update the props, labels and workflow around it.
---

Components 5 has one `SchemaEditor`: the tree editor. It replaces the drill-down table editor of Components 4 at the same import path, `@cratis/components/SchemaEditor`. The change is breaking because the component's props, workflow, labels, markup and styling parts all change. Nothing else in the package changes with it.

## What changed

| Components 4 | Components 5 |
| --- | --- |
| A table of one level, with a breadcrumb to drill into nested objects and item definitions | One tree: nested properties are shown under their parent |
| An **Edit**, **Save** and **Cancel** workflow around the table | No workflow. Every edit applies and is reported through `onChange`; the host decides when to save |
| `canEdit`, `canNotEditReason`, `editMode`, `saveDisabled`, `cancelDisabled`, `onSave`, `onCancel` | Removed. Use `readOnly` to show the tree without editing it |
| `eventTypeName` | Removed. Render a title with `header` |
| `typeFormats`: any JSON type with formats such as `guid`, `date-time`, `int32` | A fixed set of types: text, number, yes or no, date, time, lists of text and numbers, objects and lists of objects. Other formats are not kept |
| `labels: Partial<SchemaEditorLabels>` with string fields | `labels?: SchemaEditorLabels` with different keys; labels about one property are functions of its name |
| Property names validated as identifiers | Blank, reserved and duplicate names are rejected. Add other rules with `validatePropertyName` |
| `ChangeHandler<JsonSchema>` | `onChange: (schema: JsonSchema) => void` |
| No concepts, key, or required toggle | `concepts`, `allowKeyProperty` and `allowRequired` |
| No extension points | `header`, `footer`, the per-row slots, and controlled mode |

The `JsonSchema`, `JsonSchemaProperty`, `NavigationItem`, `Json`, `TypeFormat` and `DEFAULT_TYPE_FORMATS` exports stay where they were, so `ObjectContentEditor` and other consumers of those types are unaffected. `SchemaEditorLabels` and `defaultSchemaEditorLabels` keep their names with new contents.

## Update your code

1. Remove the edit workflow. If you used Save and Cancel, keep the last saved schema yourself and place your own buttons next to the editor:

    ```tsx
    // Components 4
    <SchemaEditor schema={schema} canEdit editMode onChange={setDraft} onSave={save} onCancel={revert} />

    // Components 5
    <SchemaEditor schema={draft} onChange={setDraft} />
    <Button onClick={save}>Save</Button>
    <Button onClick={revert}>Cancel</Button>
    ```

2. Replace `eventTypeName` with a `header`, and `canEdit={false}` with `readOnly`.
3. Rename the labels you localized. Each new label is documented on `SchemaEditorLabels`; any you leave out stays English.
4. Import the stylesheet again if you use per-area sheets: `@cratis/components/SchemaEditor/styles` now carries only the tree editor's rules.
5. Replace selectors that targeted the old markup. Style the new stable parts instead: `root`, `row`, `name`, `badge`, `remove`, and the rest listed in [Styling](../SchemaEditor/index.md#styling).
6. Re-check any schema that used formats beyond `date` and `time`, or `integer`. They read back as a number or text, and [what is not preserved](../SchemaEditor/json-schema.md#what-is-not-preserved) lists the rest. A host that must keep them should merge the editor's output into its own schema instead of replacing it.

## Verify

- Edit a schema containing a nested object and a list of objects, and compare the emitted schema with what you store.
- Rename a required property and confirm the `required` list follows it.
- Run your accessibility checks against the new markup: every control is a button, input or checkbox, and a type is shown as text.
