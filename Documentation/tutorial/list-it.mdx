import { Steps, Aside } from '@astrojs/starlight/components';

Start with the read side: render the generated observable `AllAuthors` query as a table. Complete the [tutorial prerequisites](./index.md#before-you-start) first: this chapter needs the running Arc library backend, generated `src/Authors/Author.ts`, and the providers and CSS from [Getting started](/components/getting-started/). An empty result is fine; you will add an author in the next chapter.

<Steps>

1. **Render the table.** `DataTableForObservableQuery` takes the query proxy, subscribes to it, and renders each result as a row. You describe the columns with the Cratis-owned `Column` marker. Its `field` string must match a property on the generated `Author` read model:

    ```tsx title="src/Authors.tsx"
    import { Page } from '@cratis/components/Common';
    import { Column, DataTableForObservableQuery } from '@cratis/components/DataTables';
    import { AllAuthors } from './Authors/Author'; // generated observable query proxy

    export const Authors = () => (
        <Page title='Authors' showTitle>
            <DataTableForObservableQuery query={AllAuthors} emptyMessage='No authors yet'>
                <Column field='name' header='Name' sortable />
            </DataTableForObservableQuery>
        </Page>
    );
    ```

2. **Put it on screen.** Render `<Authors />` inside the providers from [Getting started](/components/getting-started/) — in the Arc tutorial's `src/App.tsx`, that means replacing its plain list with this component. Run the frontend and open the page. You see a table with a **Name** column: _Loading…_ until the first result arrives, then one row per author you registered in the Arc tutorial, or _No authors yet_ if there are none. A failed query shows _Could not load data._ instead of the empty message; an unauthorized query shows _You are not authorized to view this data._

</Steps>

`Page` is the layout root for a routable view: a column that fills its parent. Here `showTitle` renders **Authors** as a level-one heading. Without it, `title` alone is not visible; neither prop sets the browser tab title.

## Check the first result

| What you see | What it means | What to do |
| --- | --- | --- |
| `Loading…` with no rows | The first result is pending | If it persists, inspect the query request and backend connection |
| `No authors yet` | A successful query returned no authors | Continue to the add-author chapter |
| Author names | A successful result supplied rows | Compare them with your library data |
| `Could not load data.` | The query failed | Inspect the failed request and backend error, not the empty-state text |
| `You are not authorized to view this data.` | The query is unauthorized | Check application authentication and backend authorization |

For connection failures, use [Commands or queries do not reach the backend](/components/troubleshooting/#commands-or-queries-do-not-reach-the-backend). An unstyled table is a separate [CSS setup problem](/components/troubleshooting/#components-render-without-styles), not evidence that the query failed.

## What you didn't write

There is no application `fetch`, `useEffect`, or subscription to maintain here. `DataTableForObservableQuery` uses Arc's observable-query runtime and renders the delivered rows and query status. When that observable delivers a changed result, the table re-renders. Registering an author is a separate operation; the next chapter lets you observe the command and the subsequent query update.

<Aside type='note' title='Live, because the query is observable'>
    The liveness comes from the query being observable on the C# side: `AllAuthors` returns
    an `ISubject<IEnumerable<Author>>` built with `Observe()`. If you only need the data
    once, use `DataTableForQuery` with a non-observable query instead. If you want the values
    rather than a table — to summarize or render custom markup — call `AllAuthors.use()`.
    Same proxy, different consumption.
</Aside>

## Keep field names aligned

The generated query and its row values are typed, but `Column.field` is currently a plain string and the compiler does not validate it against the read model. Keep field names aligned with the generated row type and update them when the backend property changes. For custom cells, use `Column<Author>` with a typed `body` callback so row-property access is compiler-checked. A misspelled raw `field` value is a runtime display/configuration error rather than a TypeScript error.

## What you built

- A library screen that lists every author in a table,
- bound to the `AllAuthors` query with **no subscription or fetch code**,
- that re-renders when the observable query delivers a new result.
