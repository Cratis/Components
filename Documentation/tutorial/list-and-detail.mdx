import { Steps, Aside } from '@astrojs/starlight/components';

Replace the table-and-button screen from [Act on the list](./act-on-it.mdx) with `DataPage`: an author list, a selection-aware action row, and a resizable books panel. Keep `src/AddAuthor.tsx` from that chapter.

This chapter also requires the generated `BooksForAuthor` query in `src/Books/Book.ts` and `AddBook` command in `src/Books/AddBook.ts` from [Arc's Relate your slices](/arc/tutorial/books-and-relationships/). If they are missing, complete that backend chapter and regenerate proxies first. The final screen imports icons directly, so declare `react-icons` in your frontend package before using its imports:

```bash
npm install react-icons
```

The selected `Author.id` has two jobs: it becomes `BooksForAuthor`'s `authorId` query argument and `AddBook`'s `authorId` command value. A new `bookId` identifies the book, not its author.

<Steps>

1. **Describe the detail panel.** It's an ordinary component that receives the selected row as `item`. Type it with `IDetailsComponentProps<Author>` so `item` is the generated `Author`, then read that author's books with the `BooksForAuthor` proxy:

    ```tsx title="src/AuthorDetails.tsx"
    import type { Guid } from '@cratis/fundamentals';
    import type { IDetailsComponentProps } from '@cratis/components/DataPage';
    import type { Author } from './Authors/Author';
    import { BooksForAuthor } from './Books/Book'; // generated observable query proxy

    const Books = ({ authorId }: { authorId: Guid }) => {
        const [books] = BooksForAuthor.use({ authorId });
        if (!books.isAuthorized) return <p role='alert'>You cannot view these books.</p>;
        const isLoading = books.isPerforming || books.isReady === false;
        if (books.hasExceptions || books.isValid === false || (!isLoading && books.isSuccess === false)) {
            return <p role='alert'>Could not load books.</p>;
        }
        if (isLoading && !books.hasData) return <p>Loading books…</p>;
        if (books.data.length === 0) return <p>No books yet.</p>;
        return (
            <ul>
                {books.data.map((book) => (
                    <li key={String(book.id)}>{book.title}</li>
                ))}
            </ul>
        );
    };

    export const AuthorDetails = ({ item }: IDetailsComponentProps<Author>) => (
        <section aria-label={`Books by ${item.name}`}>
            <h2>{item.name}</h2>
            <Books key={String(item.id)} authorId={item.id} />
        </section>
    );
    ```

    The query is scoped to one author and observable, so the list stays current while the panel is open. The panel owns its status because it runs its own query: denied access takes priority, followed by exceptions or invalid arguments. A performing or not-ready result is still loading; existing books stay visible during a refresh. Once loading ends, an unsuccessful result is a failure even without exceptions. Only a successful empty result shows **No books yet.** The panel's heading identifies the selected author; the books beneath it come from this separate query, not an automatic related-data fetch by `DataPage`.

    The `key` ties the `Books` component's React state to the selected author. Selecting another author changes the key and remounts that child. That author's books may already be available; expect **Loading books…** only while the query has no ready result.

2. **Add the book dialog.** It is the same shape as `AddAuthor`, with two required values the user doesn't type: the author the book belongs to and a new book id. Both go in `initialValues`:

    ```tsx title="src/AddBook.tsx"
    import { useState } from 'react';
    import { Guid } from '@cratis/fundamentals';
    import { CommandDialog } from '@cratis/components/CommandDialog';
    import { InputTextField } from '@cratis/components/CommandForm';
    import { AddBook } from './Books/AddBook'; // generated proxy

    export const AddBookDialog = ({ authorId }: { authorId: Guid }) => {
        const [bookId] = useState(() => Guid.create());
        return (
            <CommandDialog<AddBook>
                command={AddBook}
                title='Add book'
                okLabel='Add'
                initialValues={{ authorId, bookId }}
            >
                <InputTextField<AddBook> value={(command) => command.title} title='Title' />
            </CommandDialog>
        );
    };
    ```

    `authorId` comes from the selected author; `bookId` is created once per dialog mount. `initialValues` puts both on the command even though neither has a visible field. The user supplies only the title. If the Arc tutorial's `src/AddBook.tsx` already exports this component, reuse it.

3. **Assemble the page.** `DataPage` takes the query, the columns, the menu actions, and the detail component. Selection, the resizable split, and hiding the panel when nothing is selected come built in. Menu item commands take no arguments, so the page records the selected author through `onSelectionChange` and reads it when **Add book** runs:

    ```tsx title="src/Authors.tsx"
    import { useState } from 'react';
    import { useDialog } from '@cratis/arc.react/dialogs';
    import { Column, DataPage, MenuItem } from '@cratis/components/DataPage';
    import { FaBook, FaPlus } from 'react-icons/fa6';
    import { AllAuthors, type Author } from './Authors/Author'; // generated proxy
    import { AddAuthor } from './AddAuthor';
    import { AddBookDialog } from './AddBook';
    import { AuthorDetails } from './AuthorDetails';

    export const Authors = () => {
        const [selected, setSelected] = useState<Author | null>(null);
        const [AddAuthorWrapper, showAddAuthor] = useDialog(AddAuthor);
        const [AddBookWrapper, showAddBook] = useDialog(AddBookDialog);

        return (
            <div style={{ height: '100vh' }}>
                <DataPage
                    title='Authors'
                    query={AllAuthors}
                    dataKey='id'
                    emptyMessage='No authors yet'
                    detailsComponent={AuthorDetails}
                    onSelectionChange={(event) => setSelected(event.value)}
                >
                    <DataPage.MenuItems>
                        <MenuItem
                            label='Add author'
                            icon={FaPlus}
                            command={() => void showAddAuthor()}
                        />
                        <MenuItem
                            label='Add book'
                            icon={FaBook}
                            disableOnUnselected
                            command={() => {
                                if (selected) {
                                    void showAddBook({ authorId: selected.id });
                                }
                            }}
                        />
                    </DataPage.MenuItems>
                    <DataPage.Columns>
                        <Column field='name' header='Name' sortable />
                    </DataPage.Columns>
                </DataPage>
                <AddAuthorWrapper />
                <AddBookWrapper />
            </div>
        );
    };
    ```

    `DataPage` keeps track of the selected row. `onSelectionChange` copies it into `selected` so **Add book** can use it; this does not make the selection controlled. `dataKey='id'` uses the author's unique, stable id to retain selection when a ready query result replaces that row with a new object. It cannot retain an author absent from the returned page.

    The icons come from `react-icons`. Components depends on it internally, but add `react-icons` to your own `package.json` when your code imports it, so strict package managers resolve it.

4. **Try it.** Add a book to one of your authors:

    1. With no selection, confirm that **Add book** is disabled.
    2. Select an author. Check that the action enables and the right-hand heading names that author. Wait for the books query to show their titles or a successful **No books yet.** result.
    3. Open **Add book** and enter a synthetic title such as **Sample Book**. Submit it. The dialog closes when the command succeeds. Check for the new title when `BooksForAuthor` sends an updated list too: closing the dialog does not mean the list has updated yet.
    4. Select a different author. Check that the heading and books belong to that author. If their result is not ready, expect a loading message instead. Drag the divider with a pointer to check the available space.

    <Aside type='caution' title='Recover a missing books result'>
    If the new title is missing, follow `authorId` through the table below: from `selected.id` to `showAddBook`, then to the dialog's `initialValues`. Compare it with the author id passed to `BooksForAuthor.use({ authorId })`.

    Check `books.isAuthorized` for denied access and the failure branch above for query errors. For denial, check sign-in and permissions; for failure, check the query arguments and backend response. Neither means the author has no books. See [Interpret query status](../displaying-data.md#interpret-query-status) for these result checks. If the dialog closed successfully but the title is still missing, follow [A successful command does not appear in the list](../troubleshooting.md#a-successful-command-does-not-appear-in-the-list) to check the observable query and its connection. For a rejected command, use `CommandDialog`'s [result callbacks](../CommandDialog/index.md#optional-props): `onFailed`, `onUnauthorized`, and `onValidationFailure` let you handle the reported problem.

    If an author is removed or leaves the returned page, selection can clear, closing the pane and disabling **Add book**. Select an available author and check that author's books.
    </Aside>

</Steps>

<Aside type='caution' title='Give DataPage a height'>
    `DataPage` fills the height it is given and splits it between the action bar and the
    table, so some ancestor needs a definite height. The wrapper above uses
    `height: '100vh'`; inside an application shell, a sized router outlet or a flex child
    with `min-height: 0` works too. Without one, the page falls back to a small minimum
    height. `DataPage` does not render its `title` prop, so add your own heading if the screen needs one.
</Aside>

<Aside type="tip" title="One read model per screen">
`BooksForAuthor` returns one author's books, filtered on the server, so the detail panel does not need every book to find the ones it displays. Keep queries focused on what each screen needs: the author list, this books panel, and a dashboard can use different read models without making one model serve all three. If your backend uses Chronicle, see [Read Models](/chronicle/read-models/).
</Aside>

## Check the selection handoff

| Value | Comes from | Goes to |
| --- | --- | --- |
| `selected` | `onSelectionChange(event).value` | The no-argument `MenuItem.command` closure |
| `authorId` | `selected.id` when **Add book** runs | `showAddBook({ authorId })`, then `initialValues` |
| `bookId` | `Guid.create()` on each dialog mount | `AddBook.initialValues` |
| Books query argument | The details component's `item.id` | `BooksForAuthor.use({ authorId })` |

`disableOnUnselected` controls action availability; it does not pass a row into the callback. Keep the `if (selected)` guard and selection state. The backend must still authorize the command and validate its current target; a visible author or enabled action grants no permission. Here the typed `AuthorDetails` supplies row-type inference; without a typed details component, use explicit `DataPage` generics as in the [list-screen recipe](/components/list-screen-with-actions/).

If **Add** stays disabled, check that `initialValues` supplies `authorId` and `bookId` and that `title` has a value. Follow [CommandDialog validation](../CommandDialog/index.md#validation-and-when-confirm-enables) for the rules that enable the button. If books appear under the wrong name, compare the selected author, `item.id`, the query's `authorId`, and the result being displayed; see [A detail panel shows the previous author's books](../troubleshooting.md#a-detail-panel-shows-the-previous-authors-books). For a collapsed layout, use the height warning above. Check that your application shell supplies a visible page heading; `DataPage.title` alone does not.

## Look back at what you built

Three chapters ago we had generated proxies and no screen. Now we have a real library back office:

- **Chapter 1** — a live table from `AllAuthors`, bound to an observable query with no fetch or subscription code.
- **Chapter 2** — add authors through `CommandDialog` + `useDialog`, with required values in `initialValues` and the table rendering subsequent query updates.
- **Chapter 3** — a `DataPage` list-and-detail layout: selection, menu actions, a resizable panel showing each author's books, and a selection-aware **Add book** action.

The reusable pattern is a query-backed list plus command dialogs, with the selected row's stable id passed explicitly to the next query or command. Field accessors and row-property access are typed against generated contracts; `Column.field` remains a plain string that you must keep aligned with the read model.
