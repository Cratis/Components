import { Steps, Aside } from '@astrojs/starlight/components';

Replace the table-and-button screen from [Act on the list](./act-on-it.mdx) with `DataPage`: an author list, a selection-aware action row, and a resizable books panel. Keep `src/AddAuthor.tsx` from that chapter.

This chapter also requires the generated `BooksForAuthor` query in `src/Books/Book.ts` and `AddBook` command in `src/Books/AddBook.ts` from [Arc's Relate your slices](/arc/tutorial/books-and-relationships/). If they are missing, complete that backend chapter and regenerate proxies first. The final screen imports icons directly, so declare `react-icons` in your frontend package before using its imports:

```bash
npm install react-icons
```

The selected `Author.id` has two jobs: it becomes `BooksForAuthor`'s `authorId` query argument and `AddBook`'s `authorId` command value. A new `bookId` identifies the book, not its author.

<Steps>

1. **Describe the detail panel.** It's an ordinary component that receives the selected row as `item`. Type it with `IDetailsComponentProps<Author>` so `item` is the generated `Author`, then read that author's books with the `BooksForAuthor` proxy:

    ```tsx title="src/AuthorDetails.tsx"
    import type { Guid } from '@cratis/fundamentals';
    import type { IDetailsComponentProps } from '@cratis/components/DataPage';
    import type { Author } from './Authors/Author';
    import { BooksForAuthor } from './Books/Book'; // generated observable query proxy

    const Books = ({ authorId }: { authorId: Guid }) => {
        const [books] = BooksForAuthor.use({ authorId });
        if (!books.isAuthorized) return <p role='alert'>You cannot view these books.</p>;
        if (books.hasExceptions) return <p role='alert'>Could not load books.</p>;
        if (books.isPerforming && !books.hasData) return <p>Loading books…</p>;
        if (books.data.length === 0) return <p>No books yet.</p>;
        return (
            <ul>
                {books.data.map((book) => (
                    <li key={String(book.id)}>{book.title}</li>
                ))}
            </ul>
        );
    };

    export const AuthorDetails = ({ item }: IDetailsComponentProps<Author>) => (
        <section aria-label={`Books by ${item.name}`}>
            <h2>{item.name}</h2>
            <Books key={String(item.id)} authorId={item.id} />
        </section>
    );
    ```

    The query is scoped to one author and observable, so the list stays current while the panel is open. The panel owns its loading, unauthorized, failed, and empty states because it runs its own query. A denied or failed query is not an empty book list.

    The `key` matters. `DataPage` keeps the details component mounted when the selection moves to another row, and a query hook keeps its last result when its arguments change until the new result arrives. Without the key, selecting another author briefly shows the previous author's books under the new name. Keying the child by author id mounts a fresh query per author, so the panel shows *Loading books…* instead.

2. **Add the book dialog.** It is the same shape as `AddAuthor`, with two required values the user doesn't type: the author the book belongs to and a new book id. Both go in `initialValues`:

    ```tsx title="src/AddBook.tsx"
    import { useState } from 'react';
    import { Guid } from '@cratis/fundamentals';
    import { CommandDialog } from '@cratis/components/CommandDialog';
    import { InputTextField } from '@cratis/components/CommandForm';
    import { AddBook } from './Books/AddBook'; // generated proxy

    export const AddBookDialog = ({ authorId }: { authorId: Guid }) => {
        const [bookId] = useState(() => Guid.create());
        return (
            <CommandDialog<AddBook>
                command={AddBook}
                title='Add book'
                okLabel='Add'
                initialValues={{ authorId, bookId }}
            >
                <InputTextField<AddBook> value={(command) => command.title} title='Title' />
            </CommandDialog>
        );
    };
    ```

    If the Arc tutorial's `src/AddBook.tsx` already exports this component, reuse it.

3. **Assemble the page.** `DataPage` takes the query, the columns, the menu actions, and the detail component. Selection, the resizable split, and hiding the panel when nothing is selected come built in. Menu item commands take no arguments, so the page records the selected author through `onSelectionChange` and reads it when **Add book** runs:

    ```tsx title="src/Authors.tsx"
    import { useState } from 'react';
    import { useDialog } from '@cratis/arc.react/dialogs';
    import { Column, DataPage, MenuItem } from '@cratis/components/DataPage';
    import { FaBook, FaPlus } from 'react-icons/fa6';
    import { AllAuthors, type Author } from './Authors/Author'; // generated proxy
    import { AddAuthor } from './AddAuthor';
    import { AddBookDialog } from './AddBook';
    import { AuthorDetails } from './AuthorDetails';

    export const Authors = () => {
        const [selected, setSelected] = useState<Author | null>(null);
        const [AddAuthorWrapper, showAddAuthor] = useDialog(AddAuthor);
        const [AddBookWrapper, showAddBook] = useDialog(AddBookDialog);

        return (
            <div style={{ height: '100vh' }}>
                <DataPage
                    title='Authors'
                    query={AllAuthors}
                    emptyMessage='No authors yet'
                    detailsComponent={AuthorDetails}
                    onSelectionChange={(event) => setSelected(event.value)}
                >
                    <DataPage.MenuItems>
                        <MenuItem
                            label='Add author'
                            icon={FaPlus}
                            command={() => void showAddAuthor()}
                        />
                        <MenuItem
                            label='Add book'
                            icon={FaBook}
                            disableOnUnselected
                            command={() => {
                                if (selected) {
                                    void showAddBook({ authorId: selected.id });
                                }
                            }}
                        />
                    </DataPage.MenuItems>
                    <DataPage.Columns>
                        <Column field='name' header='Name' sortable />
                    </DataPage.Columns>
                </DataPage>
                <AddAuthorWrapper />
                <AddBookWrapper />
            </div>
        );
    };
    ```

    The icons come from `react-icons`. Components depends on it internally, but add `react-icons` to your own `package.json` when your code imports it, so strict package managers resolve it.

4. **Try it.** With no selection, **Add book** is disabled. Select an author: the action enables and the books query loads in the right-hand panel. Add a synthetic title such as **Sample Book**. First the dialog closes on command success; then the title appears when `BooksForAuthor` delivers the updated result. Select a different author and confirm that the panel changes to that author's books. Drag the divider to check the available space.

</Steps>

<Aside type='caution' title='Give DataPage a height'>
    `DataPage` fills the height it is given and splits it between the action bar and the
    table, so some ancestor needs a definite height. The wrapper above uses
    `height: '100vh'`; inside an application shell, a sized router outlet or a flex child
    with `min-height: 0` works too. Without one, the page falls back to a small minimum
    height. `DataPage` does not render its `title` prop, so add your own heading if the screen needs one.
</Aside>

<Aside type="tip" title="One read model per screen">
The detail panel reads books through `BooksForAuthor`, a query *built for this job*: one author's books, filtered on the server. Resist the urge to make one giant read model serve every view. A list query, a detail query, and a dashboard query can each read their own purpose-built model; they're cheap to add and they never fight each other. With Chronicle, see [Read Models](/chronicle/read-models/).
</Aside>

## Check the selection handoff

| Value | Comes from | Goes to |
| --- | --- | --- |
| `selected` | `onSelectionChange(event).value` | The no-argument `MenuItem.command` closure |
| `authorId` | `selected.id` when **Add book** runs | `showAddBook({ authorId })`, then `initialValues` |
| `bookId` | `Guid.create()` on each dialog mount | `AddBook.initialValues` |
| Books query argument | The details component's `item.id` | `BooksForAuthor.use({ authorId })` |

`disableOnUnselected` controls action availability; it does not pass a row into the callback. Keep the `if (selected)` guard and selection state. Here the typed `AuthorDetails` supplies row-type inference; without a typed details component, use explicit `DataPage` generics as in the [list-screen recipe](/components/list-screen-with-actions/).

If **Add** stays disabled, inspect `authorId`, `bookId`, and `title`, not just the visible title field. If books appear under the wrong name while switching authors, retain the keyed `Books` child. For a collapsed layout, use the height warning above. Check that your application shell supplies a visible page heading; `DataPage.title` alone does not.

## Look back at what you built

Three chapters ago we had generated proxies and no screen. Now we have a real library back office:

- **Chapter 1** — a live table from `AllAuthors`, bound to an observable query with no fetch or subscription code.
- **Chapter 2** — add authors through `CommandDialog` + `useDialog`, with required values in `initialValues` and the table rendering subsequent query updates.
- **Chapter 3** — a `DataPage` list-and-detail layout: selection, menu actions, a resizable panel showing each author's books, and a selection-aware **Add book** action.

The reusable pattern is a query-backed list plus command dialogs, with the selected row's stable id passed explicitly to the next query or command. Field accessors and row-property access are typed against generated contracts; `Column.field` remains a plain string that you must keep aligned with the read model.
